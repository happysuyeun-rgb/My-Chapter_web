이 책의 목표는 코딩 문법을 배우는 것이 아닙니다.

AI와 함께 실제로 공개하고 사용할 수 있는 홈페이지 하나를 끝까지 완성하는 것이 목표입니다.

실습에서는 다음 흐름을 경험합니다.

기획 ↓ 사이트 구조 ↓ 콘텐츠 ↓ 디자인 방향 ↓ React + Vite 제작 ↓ GitHub 저장 ↓ Netlify 배포 ↓ 도 메인과 문의 연결 ↓ 오픈 전 검수 완성할 홈페이지의 기본 범위는 서비스 소개와 문의를 중심으로 한 비즈니스 홈페이지입니다.

회원가입, 결제, 복잡한 관리자 기능처럼 사용자 데이터와 중요한 거래가 얽히는 기능은 이 책의 핵심 실습 범 위에서 제외합니다. AI로 구현할 수 있느냐보다 안전하게 운영할 수 있느냐가 더 중요하기 때문입니다.

이 책의 마지막에 여러분이 얻게 되는 것은 코드 한 묶음이 아니라, 필요한 홈페이지를 기획하고 AI에게 작업을 나누어 맡기고 직접 검수해 공개하는 전체 흐름입니다.

02 시작 전에 준비할 것 실습에 필요한 기본 도구는 다음과 같습니다.

  • AI 대화 도구: 기획, 문구, 검토에 사용 • Cursor: AI와 함께 코드를 만들고 수정하는 편집기 • Node.js: React + Vite 프로젝트를 로컬에서 실행하기 위한 환경 • Git: 프로젝트의 변경 이력을 기록 • GitHub: Git 저 장소를 온라인에 보관하고 배포 서비스와 연결 • Netlify: 완성한 홈페이지를 인터넷에 배포 • Chrome 등 브 라우저: 결과 확인과 오류 점검 모든 서비스를 유료로 시작할 필요는 없습니다. 다만 무료 플랜의 제공 범위와 사용량은 바뀔 수 있으므로 가입 화면과 공식 가격 페이지에서 현재 조건을 확인하세요.

화면 예시와 메뉴 이름도 서비스 업데이트에 따라 달라질 수 있습니다. 버튼 위치를 외우기보다 “프로젝트를 연다 → AI에게 작업을 요청한다 → 브라우저에서 확인한다 → Git에 저장한다 → 배포한다”는 작업 흐름을 익 히는 데 집중하세요.

처음부터 모든 계정을 만들어둘 필요도 없습니다. 해당 단계가 왔을 때 하나씩 준비하면 됩니다.

04 홈페이지를 만들기 전에 결정해야 할 3가지 홈페이지를 기획할 때 가장 먼저 결정해야 할 것은 아래 세 가지입니다.

  1. 누구에게 보여줄 것인가
  2. 무엇을 보여줄 것인가
  3. 방문자가 무엇을 하게 만들 것인가 복잡하게 들릴 수 있지만 사실 홈페이지 기획의 대부분은 이 세 질문 안에 들어 있습니다.
  4. 누구에게 보여줄 것인가 먼저 홈페이지를 방문할 사람을 생각해봅니다.

예를 들어 프리랜서 디자이너의 홈페이지라면 방문자는 다음과 같을 수 있습니다.

  • 디자인 외주를 맡기고 싶은 사람 • 프로젝트 협업자를 찾는 기업 • 디자이너의 작업물을 보고 싶은 사람 반대로 작은 공방의 홈페이지라면 방문자는 전혀 다릅니다.
  • 제품을 구매하고 싶은 사람 • 클래스 일정을 확인하고 싶은 사람 • 위치와 운영시간을 알고 싶은 사람 방문자가 달라지면 홈페이지에 보여줘야 할 내용도 달라집니다.

그래서 "예쁜 홈페이지를 만들고 싶다"보다 먼저 생각해야 하는 질문은 이것입니다.

이 홈페이지는 누가 보게 될까?

나쁜 정의 모든 사람이 보는 홈페이지 너무 넓습니다.

대상이 넓어질수록 메시지는 오히려 약해집니다.

조금 더 좋은 정의 홈페이지 제작이 필요한 소규모 사업자 더 구체적인 정의 처음 사업을 시작해서 홈페이지가 필요하지만 대행업체 비용이 부담스러운 1인사업자 이렇게 구체적일수록 홈페이지의 문구와 구성도 훨씬 쉽게 정할 수 있습니다.

  1. 무엇을 보여줄 것인가 방문자가 정해졌다면 이제 보여줄 정보를 결정해야 합니다.

많은 홈페이지가 여기에서 욕심을 냅니다.

회사 이야기, 대표 소개, 서비스, 연혁, 인증서, 뉴스, 블로그, 포트폴리오, 고객 후기까지 가능한 모든 정보를 넣으려고 합니다.

예를 들어 외주 서비스를 판매하는 홈페이지라면 방문자는 대체로 다음을 궁금해합니다.

여기는 무엇을 하는 곳이지?

정보보다 질문을 먼저 생각하세요

페이지를 구성할 때는 "어떤 메뉴를 만들까?"보다 이런 식으로 생각하는 것이 좋습니다. 방문자의 질문 "여기는 뭐 하는 곳이지?"

홈페이지에서 보여줄 내용 메인 헤드라인 + 서비스 설명 방문자의 질문 "잘하는 곳일까?"

홈페이지에서 보여줄 내용 포트폴리오 + 고객 후기 + 프로젝트 사례 방문자의 질문 "진행 방식이 복잡하지 않을까?"

홈페이지에서 보여줄 내용 작업 프로세스 방문자의 질문 "가격은 어떻게 되지?"

홈페이지에서 보여줄 내용 가격 또는 견적 안내 방문자의 질문 "문의는 어떻게 하지?"

홈페이지에서 보여줄 내용 문의 버튼 + 연락 방법 직접 해보기 내 홈페이지를 방문한 사람이 궁금해할 질문을 최소 다섯 개 적어봅니다.

예:

  1. 어떤 서비스를 제공하나요?
  2. 어떤 사람에게 필요한 서비스인가요?
  3. 실제 작업 사례가 있나요?
  4. 작업 기간은 얼마나 걸리나요?
  5. 어떻게 문의하면 되나요?

이 질문들이 이후 홈페이지의 섹션이 됩니다.

  1. 방문자가 무엇을 하게 만들 것인가 이 세 번째 질문이 특히 중요합니다.

홈페이지는 정보를 보여주는 공간이기도 하지만, 결국 방문자의 행동을 만들어내야 합니다.

예를 들어 서비스 홈페이지라면 목표는 이런 식입니다.

  • 상담 문의하기 • 견적 요청하기 • 예약하기 • 카카오톡 상담하기 • 이메일 보내기 • 제품 구매하기 • 포트폴리 오 보기 이 행동을 보통 CTA(Call to Action)라고 합니다.

쉽게 말하면, 방문자에게 다음으로 해달라고 요청하는 행동 입니다.

홈페이지의 목표는 하나가 좋습니다

처음 홈페이지를 만드는 경우 특히 중요한 원칙이 있습니다.

가장 중요한 행동 하나를 먼저 정하세요.

예를 들어 다음처럼 여러 버튼을 동시에 강조하면 방문자는 오히려 혼란스러울 수 있습니다.

서비스 보기 블로그 보기 인스타그램 보기 회사 소개 보기 이메일 보내기 상담하기 자료 다운로드 모든 것이 중요하면 결국 아무것도 중요하지 않게 됩니다.

그래서 메인 목표를 하나 정합니다.

이 홈페이지의 가장 중요한 목표는 프로젝트 문의를 받는 것이다.

그다음 보조 목표를 둘 수 있습니다.

두 번째 목표는 포트폴리오를 보게 하는 것이다.

이 정도면 충분합니다.

홈페이지 목적 한 문장으로 만들기 앞에서 정한 세 가지를 한 문장으로 합쳐봅니다.

공식처럼 사용하면 쉽습니다.

이 홈페이지는 [대상]에게 [무엇]을 보여주고, 최종적으로 [행동]하게 만드는 홈페이지다.

예: 이 홈페이지는 홈페이지 제작이 필요한 1인사업자에게 제작 서비스와 작업 사례를 보여주고, 최종적으로 프로 젝트 문의를 하게 만드는 홈페이지다.

이 문장이 이후 모든 작업의 기준이 됩니다.

를 판단할 수 있습니다.

AI에게 이렇게 요청하세요

아래 프롬프트에서 대괄호 부분을 자신의 상황에 맞게 바꿔 사용합니다.

나는 [업종/서비스] 홈페이지를 만들려고 해.

주요 방문자는 [타깃 고객]이고, 내가 제공하는 서비스는 [서비스 설명]이야.

홈페이지의 가장 중요한 목표는 방문자가 [문의/예약/구매/상담 등 원하는 행동]을 하게 만드는 것이야. 이 정보를 바탕으로

  1. 홈페이지의 핵심 목적
  2. 방문자가 궁금해할 질문
  3. 반드시 보여줘야 할 정보
  4. 메인 CTA
  5. 보조 CTA 를 정리해줘.

홈페이지를 처음 만드는 사람도 이해할 수 있도록 설명해줘.

결과 확인 AI의 답변을 그대로 사용할 필요는 없습니다.

특히 다음 항목을 확인합니다.

대상이 너무 넓지 않은가?

"모든 사람", "다양한 고객"처럼 범위가 너무 넓다면 다시 좁힙니다.

09 한 페이지 홈페이지는 어떤 순서로 구성할까?

한 페이지 홈페이지의 핵심은 사업자가 말하고 싶은 순서가 아니라 방문자가 궁금해하는 순서입니다.

서비스형 예시 Hero ↓ Service ↓ Portfolio 또는 Evidence ↓ Process ↓ FAQ ↓ Contact 필요하다면 Service 앞에 Problem을 넣을 수 있습니다.

Hero → 무엇을 하는 곳인지 Service → 어떤 도움을 주는지 Portfolio → 믿을 근거 FAQ → 문의 전 불안 해 소 Contact → 실제 행동 섹션 이름보다 역할이 먼저입니다.

10 방문자가 행동하게 만드는 CTA CTA는 방문자에게 다음 행동을 알려주는 버튼이나 문장입니다.

“더보기”보다 “서비스 자세히 보기”, “프로젝트 문의하기”처럼 클릭 후 결과를 예상할 수 있는 문구가 좋습니 다.

메인 CTA는 하나를 정하고, 필요하면 보조 CTA를 둡니다.

메인 CTA → 프로젝트 문의하기 보조 CTA → 포트폴리오 보기 홈페이지가 길다면 같은 메인 CTA를 여러 번 보여줘도 괜찮습니다. 다만 위치마다 목적과 문구가 계속 바뀌면 방문자가 헷갈립니다.

CTA 앞에는 행동할 이유가 있어야 합니다.

작업 사례 확인 ↓ 진행 방식 이해 ↓ FAQ 확인 ↓ 프로젝트 문의하기 직접 해보기 메인 CTA: ______ 보조 CTA: ______ 문구를 정하기 어렵다면 AI에게 “짧고 직관적이며 클릭 후 결과를 예상할 수 있는 CTA”를 요청하세요.

홈페이지를 만들 때 많은 사람이 디자인에서 막힙니다.

하지만 홈페이지 디자인은 처음부터 예술 작품을 만드는 일이 아닙니다.

중요한 것은 보기 좋고, 읽기 쉽고, 사용하기 쉬운 화면을 만드는 것입니다.

이번 PART에서는 복잡한 디자인 이론보다 홈페이지를 만들 때 꼭 필요한 기준만 익힙니다.

처음부터 “예쁘게” 만들려고 하면 판단 기준이 없습니다.

초보자는 다섯 가지만 봐도 충분합니다.

  • 컬러 • 폰트 • 여백 • 정렬 • 대비 컬러는 메인·보조·배경·텍스트 정도로 단순하게 시작합니다.

폰트는 한두 종류면 충분합니다.

여백은 요소를 떨어뜨려 읽을 시간을 만들어줍니다.

정렬은 텍스트와 카드의 시작점을 맞춰 화면을 안정시킵니다.

대비는 제목, 본문, 보조 설명, CTA의 중요도를 구분합니다.

화면이 어수선할 때 새로운 장식을 더하기보다 이 다섯 기준부터 다시 보세요.

  • 글자 크기가 읽기 쉽다.
  • 섹션 간 여백이 일관적이다.
  • 이미지가 깨지지 않는다.
  • 디자인 요소가 지나치게 많지 않다.
  • CTA가 다른 요소보다 잘 보인다.
  1. 모바일
  • 가로 스크롤이 없다.
  • 메뉴가 정상적으로 열린다.
  • 버튼을 쉽게 누를 수 있다.
  • 텍스트가 화면 밖으로 나가지 않는다.
  • 이미지가 이상하게 잘리지 않는다.
  • 문의 폼을 모바일에서 작성할 수 있다.
  1. 링크
  • 로고 링크가 정상이다.
  • 메뉴 링크가 정상이다.
  • CTA가 정상이다.
  • 포트폴리오 링크가 정상이다.
  • 이메일 링크가 정상이다.
  • SNS 링크가 정상이다.
  • 외부 링크가 잘못 연결되지 않았다.
  1. 문의
  • 실제로 문의를 제출해봤다.
  • 정상적으로 수신된다.
  • 성공 메시지가 표시된다.
  • 오류 상황 안내가 있다.
  • 필수 항목이 검증된다.
  • 개인정보 수집 항목을 확인했다.
  1. 이미지
  • 이미지 사용 권한을 확인했다.
  • 지나치게 큰 이미지가 없다.
  • 파일 이름이 정리되어 있다.
  • 의미 있는 이미지에 필요한 설명이 있다.
  1. SEO
  • 페이지 title을 설정했다.
  • description을 설정했다.
  • H1이 있다.
  • H2/H3 구조가 자연스럽다.
  • 정보를 전달하는 이미지에는 적절한 alt가 있고, 장식 이미지는 빈 alt로 처리되어 있다.
  • URL 구조가 이해하기 쉽다.
  1. 배포
  • 실제 URL로 접속된다.
  • HTTPS가 적용되어 있다.
  • 도메인이 정상적으로 연결된다.
  • GitHub 연동 배포를 사용한다면, 배포된 버전이 의도한 커밋과 일치한다.
  • 실제 스마트폰에서 확인했다.
  1. 보안
  • 코드에 비밀번호가 없다.
  • API 비밀 키가 노출되지 않았다.
  • 민감한 .env 파일이 Git에 포함되지 않았고, 브라우저에 노출되는 환경 변수에 비밀값이 없다.
  • 테스트 개인정보가 남아 있지 않다.
  • 사용하지 않는 인증정보가 없다.
