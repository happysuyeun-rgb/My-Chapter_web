# 서비스화 준비 (C플랜)

지금은 로컬 한 사람용입니다. 1단계에서 저장소를 작업 공간(workspace)으로 나눠 두었기 때문에, 나중에 사용자마다 폴더만 바꾸면 됩니다.

## 이미 맞춰 둔 것

- `createWorkspace(dir)`가 루트를 받습니다. 환경변수 `EBOOK_WORKSPACE`로 바꿀 수 있습니다.
- 모든 책 파일 접근은 `ws.bookHtml` / `ws.resolve`를 거쳐 작업 공간 밖으로 나가지 않습니다.
- PDF는 `renderPdf` 안에서 한 번에 하나만 돌아갑니다. 여러 사용자가 동시에 받으면 대기합니다.
- 원본은 계속 책별 `book.html`입니다. 클라우드 스토리지로 옮길 때도 파일 단위로 올리면 됩니다.

## 나중에 결정할 것

1. **로그인**  
   혼자 쓰다 소수가 쓰면 공유 비밀번호 하나로 시작할 수 있습니다. 여러 저자가 각자의 서재를 갖게 되면 세션(또는 JWT)과 사용자 id가 필요합니다. 사용자 id는 작업 공간 경로(`workspaces/<id>/`)와 같게 두면 됩니다.

2. **호스팅**  
   PDF는 헤드리스 Chrome이 필요합니다. Chrome을 넣을 수 있는 VPS나 Docker가 맞고, 정적 호스팅(Netlify 등)만으로는 PDF를 만들 수 없습니다. 미리보기 HTML은 정적 파일로 나눠 주고, `/__pdf`만 별도 워커로 빼는 구성도 가능합니다.

3. **저장 위치**  
   지금은 디스크의 `books/`, `_trash/`, `.history/`입니다. 이용자가 늘면 객체 스토리지(S3 호환)에 `book.html`과 그림 상태 JSON, 기록 스냅샷을 올리면 됩니다. `storage.mjs`의 `read`/`write`/`copyDir`만 바꾸면 라우트는 그대로입니다.

4. **요금**  
   PDF·EPUB 생성과 기록 보관이 비용을 만듭니다. 초안에는 월 몇 권까지 무료, 그 이상은 대기열 우선순위나 쪽수 제한을 두는 방식이 단순합니다.

5. **라이선스**  
   지금 쓰는 라이브러리와 폰트는 상업적으로 쓸 수 있습니다. Pretendard(OFL), pdf.js(Apache-2.0), mammoth(BSD), Paged.js(MIT), pdf-lib(MIT).
